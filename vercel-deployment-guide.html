4. Deployment Steps

  1. Commit: git add backend/app/main.py vercel.json && git commit -m "feat: Vercel CORS config" && git push origin main
  2. Open Vercel: vercel.com/new → import repo
  3. Apply settings from section 3 — framework Other, build command as above
  4. Deploy → wait for build (frontend ~5s, backend ~10s)
  5. Test: visit URL → click "Load Scenario A" → verify lab table + provenance badges + correlation cards + summary + theme toggle

CLI alternative: vercel --prod (after vercel login)

5. Known Limitations (Demo-Scope Only)

Ephemeral file storage. The uploads/ directory and backend/uploads/ reset on redeploy. PDF uploads work per-session but the file is lost after redeploy. For production: add Vercel Blob Storage or S3/R2.
In-memory database. patients_db / reports_db are in-memory dictionaries (see comments in routes). Patient data and uploaded reports reset on deploy. Demo scenarios (Load A/B) load from frontend, so those still work. For production: Vercel KV or Postgres.
4.5MB body limit. Vercel serverless functions cap request body at 4.5MB. The backend's default MAX_FILE_SIZE=10MB may need reduction to ~4MB for production. Current CBC PDF (~90KB) is well under.
Cold start. Python serverless ~1–2s on first request after idle. Not a blocker for demo.
Local development preserved. CORS still allows localhost:5173, localhost:3000, 127.0.0.1:5173. npm run dev + uvicorn unchanged.
